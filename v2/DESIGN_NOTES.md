以上是设计参考；以下是针对本作品集做出的布局选择，没有直接复制参考页面。

## 实现

1. 所有模块使用统一内容宽度和边距，避免个人介绍、作品与联系方式各有一套尺度。
2. 章节数字、中英文标题、主文案和说明形成固定信息层次；各章节使用一致的字号和间距。
3. Mirage 体感交互装置、MIRAGE 三维动画两张卡片放大为重点行；营销 PV、信息可视化放到下一行普通卡片，其他横屏三列、竖屏六列。平板横屏两列，手机横屏一列、竖屏两列。作品顺序、标题、内容和原有封面保持。
4. 个人介绍采用非对称双栏；能力卡片改为两列；联系方式与弹窗统一留白、文本宽度和对齐。
5. 移除过时的全局锚点偏移，所有导航、首屏/介绍滚轮过渡、直接带锚点链接统一定位到模块边界。字体加载后校正初始深链接。
6. 分类变化回到作品区起点，空分类提供返回全部的入口。固定分类栏只在作品区显示。
7. HANG / UNSEEN 液态字、液态金属按钮、BorderGlow、黑金/波谱主题、GSAP、18 件作品及媒体交互保留。

## 手机端迭代 — 2026-09-30

参考同一套内容层级和排版原则，并补充 [web.dev 响应式布局](https://web.dev/articles/responsive-web-design-basics) 与 [W3C 触控目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。W3C 的最低目标尺寸要求为 24 CSS 像素或满足相应间距；本次把主要手机控件设为 44–48 像素，属于针对触屏舒适度的设计选择。

- 手机采用独立标题、双手构图、明确的触碰与进入按钮，保留 opening animation、液态字和触碰发光。可以直接进入作品。
- 精简首屏页头；全屏导航覆盖四个章节，并提供黑金/波谱选择。浏览正文时用小型菜单入口，作品分类栏仍仅在作品区吸附。
- 横屏作品单列、竖屏作品双列；保留两件 Mirage 重点作品、18 件作品和原有顺序。较宽屏幕和手机横屏使用对应网格。
- 正文和联系方式采用更适合阅读的字号、行距与留白。肖像支持原有滑动，也提供显式主题按钮，两种操作同步。
- 作品详情为手机全屏视图，顶部关闭按钮保持可见；32 张桌游图片、多图模型、视频和小游戏仍使用同一套内容。简历入口仍提示文件待补充。
- 原有动效遵循减少动态效果设置。触屏按钮采用金属光效与点击波纹，反馈在操作后自动停止；鼠标/键盘继续使用共用的液态渲染画布，不为每张卡片建立渲染器。
- 触屏按钮在手指短暂静止释放时激活一次，滑动不激活；防止浏览器兼容 click 被吞掉或重复响应。阻止兼容鼠标事件把焦点移到已关闭弹窗背后，关闭后焦点返回作品卡片。原生键盘与鼠标点击保持。图片滑块、视频原生控件和嵌入游戏仍使用各自的手势。
- 菜单和作品详情的关闭入口保持可见，长内容与手机横屏下也能随时退出。
- 安全区域、动态视口高度、横屏与 320 像素窄屏单独处理；页面可缩放，未使用禁止缩放的 viewport 设置。
- 触屏菜单和章节链接直接对齐章节边界，避免长距离平滑滚动与手势惯性互相打断；到达后的模块进场动效保留。鼠标端原有滚动行为保持。

本次修改前的 V2 源码已存为工作区 `outputs/portfolio-v2-before-mobile-20260930.zip`，包含原目录结构、字体、源码和配置；媒体继续复用原版资源。V1 原版及其发布首页保持不变。Git 发布提交也可作为回退边界。

## 应用内浏览器兼容修复 — 2026-09-30

用户在实际手机中反馈 V2 没有切换到手机布局。检查发布 CSS 后发现，默认压缩目标将传统断点改写为 `(width<=767px)` 等范围语法。使用官方 Playwright Chromium 102.0.5005.40 重现了同样的标题断行、窄列卡片、导航隐藏和简介双栏错排；该内核不支持范围断点、容器单位和新视口单位。先前仅使用新版 Edge 模拟尺寸的验证未覆盖这一差异。

兼容依据：[范围断点语法的浏览器支持](https://web.dev/articles/media-query-range-syntax)、[Vite 的 CSS 兼容目标](https://vite.dev/config/build-options#build-csstarget)。

- 构建目标设为 Chrome 80 / Safari 14，发布 CSS 保留传统 `max-width` / `min-width` 条件；不依赖手机能否识别新断点语法。
- 在 `svh` / `dvh` 前提供 `vh` 回退。容器单位不可用时，封面用百分比比例盒；`aspect-ratio` 不可用时，肖像也保留固定比例。
- 缺少原生 dialog 的浏览器使用遮罩、滚动锁、焦点限制、关闭和 Escape 回退。手机导航通过 React Portal 放在页面顶层，避免被页头的层级限制挡住。
- 旧内核的兼容触摸 click 可能也是 `detail=0`。按可信事件区分手动激活与后续原生点击，防止一次手势重复激活或点穿弹窗；键盘和鼠标输入会清除触摸抑制。
- 较旧浏览器缺少 `:focus-visible` 时，按钮功能仍可正常运行，不因选择器异常中断。

测试记录及新旧对比截图位于 `outputs/portfolio-v2-qa/webview/`；其中原生 dialog 缺失路径通过单独的功能缺失模拟测试。旧内核浏览器模拟与实际手机反馈分别记录，浏览器模拟不代表逐台实机测试。

Chromium 102 与 Edge 154 的 320–1440 像素尺寸、手机横屏及主要交互均检查。旧内核检查首屏触碰、肖像滑动、32 张图的图集、关闭入口、小游戏加载与触控、复制和返回焦点。便携版 Chromium 测试程序未包含 H264 解码器，因此该程序只验证视频控件；原作品视频的真实播放使用 Edge 验证。Chrome 102 的 `image.decode()` 偶发拒绝已可绘制的图片时，测试额外验证画布像素；32 张图均可实际绘制，未改动原图文件。

修复前 V2 源码保存为 `outputs/portfolio-v2-before-webview-fix-20260930.zip`，可回退到上一轮手机适配。V1 和原有媒体继续保留。
